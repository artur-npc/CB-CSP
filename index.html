EUD-3489 · CSP — remove inline styles

Cookiebot Banner — CSP / inline-style Test

Loads the banner under a strict CSP with no 'unsafe-inline' for styles (the DigiD / zwitserleven.nl scenario) and reports every Content-Security-Policy violation the banner triggers.

1 · Active Content-Security-Policy on this page

Enforced through a <meta http-equiv> tag. The key line is style-src — it allows 'self' and this page's own nonce, but not 'unsafe-inline'. A CSP-compliant banner must render with zero style-src violations.

Note: a JS element.style.x = y assignment is not itself a CSP violation (it is CSSOM, not parsed inline content). The measurable violations come from injected <style> elements, style="…" markup attributes and setAttribute('style', …) — all of which this page catches.

5 · Regression checklist

  1. Banner opens and closes with 0 style-src violations.
  2. Accept / Deny / Customize and the details/about tabs — no violation on any interaction.
  3. Scroll-area faders render the correct gradient colour (EUD-6062).
  4. Widget / floating button and the cookie declaration page — no violations.
  5. GPC toast and the promotion banner — no violations.
  6. All templates: Swift, Elemental, Custom, US "Do not sell".
  7. Auto-blocking mode — blocked third-party elements restore correctly on consent.
  8. Old cached banner.css + new cc.js still clean.
  9. Visuals identical to a page without CSP — no layout regression.
  10. Legacy browser without adoptedStyleSheets — falls back to the <style> element (one expected style-src violation; such customers still need 'unsafe-inline').
